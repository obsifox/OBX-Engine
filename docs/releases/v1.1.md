# OBX Engine v1.1.0 — Runtime & Platform Foundation

**Release date:** 2026-09-28
**Theme:** Runtime & Platform Foundation — real platform layer, runtime host, job system, VFS, resources
**Tests:** 571 green (50 files) | **Packages:** 40 | **Baseline:** v1.0.0 audit + `docs/ROADMAP-1.9.md`

## Overview

The first milestone of the v1.0 → v1.9 roadmap. The engine no longer depends exclusively
on Node.js/headless execution patterns: all runtime behavior is expressed against a unified
`Platform` contract with working Node and deterministic Manual implementations. A real
`RuntimeHost` bootstraps windows, surfaces, input and lifecycle; a production job system
runs on real worker threads with work-stealing queues; a virtual file system mounts
memory, physical and package stores under virtual paths; a resource manager loads, caches
and tracks dependencies over the VFS.

## What's New

### Platform Abstraction (`@obx/platform`)

Unified `Platform` API covering every required subsystem:

- **Window** — `HeadlessWindow` (title/size/visibility/close, resize events)
- **Surface** — `PixelSurface` RGBA buffers with resize (renders via `@obx/rendering`)
- **Input** — `InputBridge` event injection (key/pointer/wheel/text) with history
- **FileSystem** — OS-level file operations (`NodeFileSystem`, in-memory for manual)
- **Timing** — high-resolution `now()`, sync `sleep()`, one-shot + repeating timers
- **Threads** — `ThreadHandle` message-passing workers: **real `node:worker_threads`**
  on Node, deterministic pump-based simulation on Manual
- **NativeEvents** — typed event bus with history (resize/focus/blur/close/drop/clipboard)
- **Clipboard** — text read/write/clear
- **ApplicationLifecycle** — enforced state machine
  (created→starting→running→suspending→suspended→resuming→stopping→stopped)
- **PlatformCapabilities** — feature queries per platform

Implementations: `NodePlatform` (real fs/timing/threads) and `ManualPlatform`
(deterministic clock, timers, thread pumping) — both fully tested (15 tests).

### Runtime Host (`RuntimeHost` in `@obx/runtime`)

- Application bootstrap: window creation, rendering surface creation, input initialization
- Engine initialization and main loop wiring over the existing `GameLoop` (Rule 1: extend, not rebuild)
- Frame timing with fixed-delta deterministic stepping (`step(deltaMs)`) for tests/CI
- Runtime startup/shutdown with lifecycle enforcement
- Error handling: per-frame isolation with error capture and `onError` reporting
- Existing engine systems run through the host (verified with ECS + rendering in tests and demo)

### Job System (`@obx/jobs`)

```text
JobSystem ── WorkerPool (real threads) / InlineExecutor (deterministic)
├── JobHandle (states, cancel, wait, listeners)
├── JobFence (multi-job joins)
├── TaskGraph (topological execution, cycle detection, dep results)
├── WorkStealingQueue (push/take/steal)
└── Main-thread queue (runOnMainThread/drainMainThread)
```

- Parallel jobs on **real worker threads** (payload + self-contained function contract)
- Job dependencies via `TaskGraph` with dependency results passed to consumers
- Synchronization (`JobFence.wait`), cancellation, error propagation
- Main-thread synchronization queue
- Deterministic testing through `InlineExecutor` (deferred pump mode)

### Virtual File System (`@obx/vfs`)

- `VirtualPath` — normalization, join/parent helpers, **traversal protection** (`..` escapes rejected)
- `MemoryFileSystem` — in-memory store with directory semantics
- `PhysicalFileSystem` — maps virtual paths onto an OS root (via `Platform.files`)
- `PackageFileSystem` — read-only packaged entries
- `MountSystem` (`VirtualFileSystem`) — mount/unmount with longest-prefix routing and merged listings

### Resource Management (`@obx/resources`)

- `ResourceLoader` registry (typed, extension-based selection)
- `ResourceHandle` — refcounted (`retain`/`release`), states (loading/ready/failed/unloaded)
- `ResourceCache` — hit/miss/invalidation statistics
- `ResourceManager` — sync + async loading, unloading with reference guards,
  dependency tracking (declared by loaders), **cascade invalidation** to dependents,
  version tracking across reloads
