# v0.10 — ObsiFox Studio: Editor, Project System & Extensions

**Tag:** `v0.10.0` · **Date:** 2026-09-28 · **Scope:** editor · project · extensions

The editor foundation of **ObsiFox Studio**: a complete scene-editing model with
undo/redo commands, inspector schemas, transform tools, console, profiler and a 2D
viewport — plus the project system (manifest v2, migration, standard folder layout,
asset index) and an editor extension registry with ten contribution kinds and strict
error isolation.

## What's inside

- **@obx/editor (15 tests)** — `SceneDocument` (tree with typed editor nodes,
  add/remove/rename/reparent with cycle rejection, `findByName`, `isAncestor`,
  snapshot/restore), `CommandStack` (undo/redo with depth limit, transactions that
  commit as `CompositeCommand`), commands: `AddNodeCommand` (snapshot-based redo),
  `RemoveNodeCommand`, `RenameNodeCommand`, `ReparentNodeCommand`, `SetPropertyCommand`
  (name, `transform.*` and custom property paths with correct undo), `CompositeCommand`
  (reverse-order undo), `Selection` (select/toggle/add/clear), `Inspector` +
  `defaultInspectorSchemas` (Node2D/Camera/Light descriptors, `describe`/`read`/
  `validate` with kind + min/max checks), `TransformTool` (select/translate/rotate/scale
  with snap steps 0.5 / 15° / 0.25 and 0.01 scale floor), `EditorConsole` (levels,
  filters, counts), `Profiler` (per-label average/max/count report, frame total),
  `Viewport` (2D editor camera, world↔screen, pan, anchored zoomAt, frame-bounds),
  `EditorSession` bundling every part.
- **@obx/project (8 tests)** — `ProjectManifest` (format/name/version/engine/
  dependencies/settings/plugins), `createManifest` with name validation,
  `Project.create` + in-memory file store (`writeFile`/`readFile`/`listFiles`/`resolve`
  with traversal protection), settings, `addPlugin`, `addDependency` +
  `checkDependencies` (missing list), `serialize`, `standardFolders` (11 standard
  project folders), `migrateManifest` (v1 → v2: `width`/`height` settings fold into
  `render.*` with defaults, future formats rejected), `satisfies` semver ranges
  (`^` `~` `>=` exact), `AssetIndex` (path/type/meta records, byType, missing-vs-project
  scan, serialize/restore), `ProjectError`.
- **@obx/extensions (5 tests)** — `ExtensionRegistry` with `register`/`unregister`/
  `activate`/`deactivate` lifecycle and `ExtensionContext` (state map, log, chained
  `executeCommand`); contributions: commands, panels (locations + order), menus
  (menu + commandId + order), inspectors (type + priority), tools, gizmos (node-type
  bound), importers (extension lists), asset types, node types; lookups
  (`inspectorFor`/`gizmoFor`/`importerFor`/`assetTypeFor`/`createNode`); `errorsFor`
  fault isolation — a throwing extension records the error and never breaks the
  registry; `stats` per extension (active/errors/contributions).

## Output

`examples/v10-demo` — a full **ObsiFox Studio** mock workbench driven by the real
editor/project/extensions APIs: an 8-node scene (Camera3D, Sun, Hero→Blade, Terrain→VFX)
edited through five commands plus a batch transaction (undo depth 5, redo open),
selection of 2 nodes, inspector showing `hp = 140` with a passing and a rejected
validation, snapped translate drag (`{x: 1, z: -0.5}`), viewport pan + anchored zoom,
console (3 info / 1 warn / 1 error), profiler report (render 5.4 ms, update 2.25 ms,
script 0.9 ms), a manifest v2 project with 11 folders and 13 files (deps satisfied,
legacy manifest migrated to `render.width: 320`), 2 indexed assets with 1 missing, and
a scene-tools extension contributing 10 pieces with 0 errors. Rendered frame:
`examples/v10-demo/output/frame.png` (640×360) · screenshot card:
`docs/screenshots/v10-update.svg`.
