# OBX Engine v1.0.0 — Stable

**Release date:** 2026-09-28

**Tests:** 513 green (45 files) | **Packages:** 36 | **Docs:** 17 guides

## Overview

OBX Engine reaches 1.0. The API surface is frozen under semantic versioning for the
1.x line, the engine gains a sandboxed plugin system, a signed package marketplace with
lockfile-based installs, 13 project templates and a complete documentation set.

## What's New

### Plugin System (§39)

- `parsePluginManifest` — validated manifests: id, name, version, engine range, permissions,
  dependencies, license.
- `PluginLoader` — register/resolve/load/start/stop/tick lifecycle with dependency-ordered
  loading (cycle + missing-dep detection) and per-plugin error isolation.
- `PluginSandbox` — eight permissions (`file.read`, `file.write`, `network`, `native`,
  `scripting`, `rendering`, `physics`, `audio`); violations are recorded and the call
  is blocked without crashing the host.
- Engine compatibility gates (`engine: "^1.0.0"`) enforced at load.

### Package Manager & Marketplace (§56-57)

- `Registry` — publish five package kinds (engine, plugin, template, asset, native) with
  `fnv1a` content checksums, versions/best queries, signature sign/verify and tamper detection.
- `PackageManager` — dependency resolution into topological trees, lockfile format 1
  (version + checksum per package) and verified restore.
- License tracking and compatibility metadata per package.

### Templates (§59)

13 starter templates in `templates/` with declarative `template.json` + placeholder
projects, instantiated via `parseTemplate` + `instantiateTemplate` (name substitution):

`empty, 2d, 3d, platformer, rpg, fps, tps, racing, open-world, visual-novel, multiplayer, application, web`

### Testing (§60)

Stress suite in `engine/tests/stress.test.ts`:

- 500-entity ECS create/destroy/serialize/load churn with invariant checks
- 50-module dependency graph: analyze → bundle → 9-stage pipeline export
- 200-tick lossy link (5% drop, jitter) with zero reliability failures
- 100 sandboxed plugins × 5 ticks with permission enforcement

### Documentation (§58)

17 guides in `docs/api/`: Getting Started, Installation, Core, ECS, 2D, 3D, Physics,
Audio, Input, UI, Networking, Scripting, Plugins, Native, CLI, Editor, Build — plus
`docs/stability.md` defining the semver 1.x policy and the frozen export surface.

## Stability Policy

- **PATCH** — fixes only. **MINOR** — additive APIs. **MAJOR** — breaking changes with
  migration notes. The export tables in `docs/stability.md` are the 1.x contract.
