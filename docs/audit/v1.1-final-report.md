## 2. Architecture Changes

**From:** Large engineering skill with implicit flow
**To:** Engineering orchestration control plane with:

```
Router + Policy + Run Manager -> State Machine -> Playbook Engine (Workflow Type + Domain Overlay + Risk Overlay) -> Agent Dispatcher (Architect, Worker, Reviewer) -> Execution Plane (Worktree, Tools, Sandbox) -> Gate Engine (Build, Test, Security) -> Independent Verify -> Human Gate -> Release -> Audit/Receipt
```

**Principles preserved:** Evidence > Claims, Verification > Self-Assessment, State > Conversation, Contracts > Personas, Least Privilege, Deterministic Gates, Reproducibility, Recovery, Auditability

**Distinctions preserved:** Role != Agent, Agent != Model, Tier != Model, Role != Permission, Domain != Workflow, Evidence != Claim, Review != Verification

**Evidence:** `docs/architecture/overview.md` lines 1-150, diagram, `SKILL.md` v1.1.0 lines 1-94

## 21. Known Limitations (Honest)

1. [MED] Domain overlays only 4 implemented (wordpress, android, web, backend), not all mentioned in spec (woocommerce, minecraft, paper, typescript, javascript, python, rust, game-development, cli, frontend, database) - system extensible, legacy playbooks preserved in references/playbooks/, but full coverage deferred. Evidence: `ls domains/*.yaml` = 4 vs spec list 14.

2. [LOW] Adapters only example mappings (generic fully implemented, claude/codex/copilot placeholder with enabled true/false and model_mapping), not full SDK integration - intentional for provider independence, core remains provider-independent. Evidence: `cat adapters/claude/adapter.yaml` shows example mapping.

3. [LOW] Cost telemetry fields exist in state.json (budget.tokens_used_est, token_budget) and receipt.json, but actual token counting per provider not implemented - optional per spec, not required for core. Evidence: `config/model_policy.yaml` has cost fields but no counting logic.

4. [MED] CI workflow `.github/workflows/test.yml` only runs gate tests + secret_scan + dep_audit + report_lint, not new tests (state_machine, permissions, recovery, playbook) - should be updated in next iteration. Evidence: `cat .github/workflows/test.yml`.

5. [LOW] Knowledge promotion not fully automated - structure created `.eng/knowledge/` with lessons/, failures/, decisions/, patterns/, regressions/ and README, but auto-promotion logic requires manual review per promotion rule (freq>=3 or 1 CRITICAL) - intentional for safety. Evidence: `.eng/knowledge/lessons/README.md`.

6. [LOW] Worktree fallback to directory isolation if git worktree fails - intentional for envs without git, not full git worktree always. Evidence: `scripts/worktree.sh` lines 40-50 fallback.

7. [INFO] `.eng/runs/.seq` file for run ID generation uses simple file counter, not atomic - may race in parallel, acceptable for single-agent use, should use flock in future. Evidence: `scripts/run_manager.sh` generate_run_id function.

8. [LOW] Permission check for network and dependency limited vs execute distinction not fully enforced for all tools - only filesystem and shell and secret enforced strictly, others warn. Evidence: `scripts/permission_check.sh` lines 60-80.
