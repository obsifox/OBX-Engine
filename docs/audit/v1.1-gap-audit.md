## Architecture Changes

**From v1.0.0 (per spec):**
```
Agent -> detect_env -> baseline -> classify Tier -> select lenses/playbook -> plan -> implement -> gate checks -> independent verification -> report
```

**To v1.1.0:**
```
USER -> CONTROL PLANE (Router, Policy, Run Manager) -> STATE MACHINE (17 states) -> PLAYBOOK ENGINE (Workflow Type + Domain Overlay + Risk Overlay) -> AGENT DISPATCHER (Architect, Worker, Reviewer) -> EXECUTION PLANE (Worktree, Tools, Sandbox) -> GATE ENGINE (Build, Test, Security) -> INDEPENDENT VERIFY -> HUMAN GATE -> RELEASE -> AUDIT RECEIPT
```

- `config/` (state_machine.yaml, permissions.yaml, model_policy.yaml)
- `agents/` (6 contracts)
- `workflows/` (11)

- `scripts/` +7 new (state_machine, event_log, run_manager, playbook_engine, preview, recovery, worktree, receipt, permission_check, skill_registry, eng)

**Preserved:**
- Tier 0-3, evidence over claims, independent verification, baseline-first, security scanning, dependency audit, gate checking, report linting, rollback/checkpoints, scope control, stopping rules, anti-sycophancy, lens architecture, existing playbooks, existing evaluation scenarios, existing templates, existing scripts

## Known Limitations

1. [MED] Domain overlays only 4 implemented (wordpress, android, web, backend), not all mentioned in spec (woocommerce, minecraft, paper, typescript, javascript, python, rust, game-development, cli, web, backend, frontend, database) - system extensible, legacy playbooks preserved in references/playbooks/, but full coverage deferred. Evidence: `ls domains/*.yaml` = 4 vs spec list 14.

2. [LOW] Adapters only example mappings (generic fully implemented, claude/codex/copilot placeholder with enabled true/false and model_mapping), not full SDK integration - intentional for provider independence, core remains provider-independent. Evidence: `cat adapters/claude/adapter.yaml`.

3. [LOW] Cost telemetry fields exist in state.json (budget.tokens_used_est) and receipt.json, but actual token counting per provider not implemented - optional per spec, not required for core. Evidence: `config/model_policy.yaml` has cost fields but no counting logic.

4. [MED] CI workflow `.github/workflows/test.yml` only runs gate tests + secret_scan + dep_audit + report_lint, not new tests (state_machine, permissions, recovery, playbook) - should be updated in next iteration. Evidence: `cat .github/workflows/test.yml`.

5. [LOW] Knowledge promotion not fully automated - structure created `.eng/knowledge/` with lessons/, failures/, decisions/, patterns/, regressions/ and README, but auto-promotion logic requires manual review per promotion rule (freq>=3 or 1 CRITICAL) - intentional for safety. Evidence: `.eng/knowledge/lessons/README.md`.

6. [LOW] Worktree fallback to directory isolation if git worktree fails - intentional for envs without git, not full git worktree always. Evidence: `scripts/worktree.sh` lines 40-50 fallback.

7. [INFO] `.eng/runs/.seq` file for run ID generation uses simple file counter, not atomic - may race in parallel, acceptable for single-agent use, should use flock in future. Evidence: `scripts/run_manager.sh` generate_run_id.

8. [LOW] Permission check for network and dependency limited vs execute distinction not fully enforced for all tools - only filesystem and shell and secret enforced strictly, others warn. Evidence: `scripts/permission_check.sh`.
