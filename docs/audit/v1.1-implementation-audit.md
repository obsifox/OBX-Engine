# Implementation Audit v1.1

**Date:** 2026-09-29
**Version:** 1.1.0
**Repo:** https://github.com/obsifox/eng-orchestrator
**Baseline:** v1.0.1 (gate hardening, 15 gate tests PASS)

## Executive Summary

Upgraded eng-orchestrator from "large engineering skill" (v1.0.1) to "engineering orchestration control plane" (v1.1.0) per Architecture Gap Closure spec.

Implemented 14 major subsystems incrementally, preserved backward compatibility, all existing tests PASS, new tests 88 PASS, total evaluation scenarios 50.

No secrets committed, no destructive behavior introduced silently.

## Before (v1.0.1)

- Single `.eng/state.json` per project
- No formal state machine (implicit flow in SKILL.md)
- No run isolation (single .eng/)
- No event log
- Roles as lenses (checklists), no executable agent contracts
- No permission matrix
- Tier only, no model routing
- Domain playbooks in `references/playbooks/` (6) but no separation WORK TYPE vs DOMAIN
- No preview mode
- No recovery system
- No worktree isolation
- Review/rework loop cap exists (2 per gate) but not formal state machine
- No receipt.json
- Knowledge only `lessons.md` unstructured
- No skill registry
- No adapter layer
- 15 eval scenarios, 15 gate tests

## After (v1.1.0)

- **State Machine:** 17 canonical states, 22+ valid transitions, 7 explicit invalid transitions, deterministic rejection via `scripts/state_machine.sh` + `config/state_machine.yaml`
- **Run Manager:** Unique RUN-YYYY-XXXXXX ID, isolated dir `.eng/runs/RUN-xxx/` with manifest.json, state.json, events.jsonl, decisions.jsonl, artifacts/, agents/, checkpoints/, verification/, receipt.json via `scripts/run_manager.sh`
- **Event Log:** Append-only `events.jsonl` with 23+ event types (RUN_CREATED, BASELINE_STARTED, GATE_PASSED, etc.) via `scripts/event_log.sh`
- **Agent Contracts:** 6 agents in `agents/*.yaml` with inputs/outputs/capabilities/permissions/tools/model_policy/delegation/termination/failure_policy/evidence_required
- **Permission Matrix:** Least privilege in `config/permissions.yaml` with 8 permission types, enforced via `scripts/permission_check.sh`, no secret.read except human
- **Model Routing:** Tier != Model separation in `config/model_policy.yaml`, low/medium/high reasoning, adapters in `adapters/` (claude, codex, copilot, generic)
- **Playbook Engine:** 11 workflow types in `workflows/` (feature, bug-fix, refactor, migration, performance, security, investigation, testing, release, documentation, incident) + 4 domain overlays in `domains/` (wordpress, android, web, backend) + risk overlays, composition via `scripts/playbook_engine.sh`
- **Preview Mode:** `scripts/preview.sh` and `scripts/eng.sh preview` shows classification without mutation
- **Recovery:** `scripts/recovery.sh` with detect, inspect, reconcile, recover, resume; checks uncommitted changes, branch divergence, checkpoint age; never destroys user changes
- **Worktree Isolation:** `scripts/worktree.sh` creates isolated worktree per run at `.eng/runs/RUN/worktree`, detects conflicts
- **Review/Rework Bounded Loop:** Formal states REVIEW -> REWORK -> VALIDATION loop with max cycles 2, then ESCALATED, no infinite loop
- **Independent Verification:** Preserved and enhanced, verifier fresh context, evidence-based
- **Receipt:** `scripts/receipt.sh` generates machine-readable receipt.json answering why tier/agents/gates selected, tools used, permissions, evidence, rework cycles, human approval
- **Structured Knowledge:** `.eng/knowledge/` with lessons/, failures/, decisions/, patterns/, regressions/, controlled promotion (freq>=3 or 1 CRITICAL)
- **Skill Registry:** `scripts/skill_registry.sh` with discover, inspect, validate, load, disable, manifest validation, permission checks, no auto remote exec
- **Adapter Layer:** `adapters/` with generic (always available), claude, codex, copilot (placeholder), provider-independent core
- **Evaluation:** Expanded from 15 to 50 deterministic scenarios in `evals/scenarios_v1_1.md` covering routing, delegation, security, recovery, verification, governance
- **Docs:** 10 new docs in `docs/` covering architecture, state-machine, agents, workflows, security, recovery, evaluation, adapters, audit

## Partially Implemented

- **Domain Overlays:** Only 4 implemented (wordpress, android, web, backend), spec mentions many more (woocommerce, minecraft, paper, typescript, etc.) - intentionally deferred, existing 6 legacy playbooks in references/playbooks/ preserved for backward compat, extensible system in place
- **Adapters:** Only generic fully implemented, claude/codex/copilot are example mappings (enabled true/false), not full provider SDK integration - intentional, core remains provider-independent
- **Knowledge Promotion:** Structure created (.eng/knowledge/), but auto-promotion logic not fully automated, requires manual review per promotion rule - intentional for safety
- **Worktree Isolation:** Git worktree support implemented, but fallback to directory isolation if git worktree fails - intentional for envs without git

## Not Implemented (Deliberately Deferred)

- **Automatic remote skill installation:** Registry supports discover/inspect/validate/load/disable, but auto-download from remote URL not implemented due to security risk (no auto remote code exec without explicit controls) - marked as BLOCKED with reason
- **Full cost telemetry:** Model routing supports token/cost tracking fields in state.json and receipt.json, but actual token counting per provider not implemented (requires provider adapter) - marked as optional, not required for core
- **Database permissions enforcement:** Permissions matrix includes database.read/write, but no actual DB enforcement (no DB in current repo) - schema preserved for future
- **Deployment execution:** Permissions include deployment.execute=approval_required, but actual deployment not implemented (requires project-specific logic) - gated by human approval

## Recovery

### Behavior

- detect: finds stale runs (non-terminal, old timestamp)
- inspect: shows last valid state, last event, last artifact, last checkpoint, git state, fs state, worktree state, unfinished transitions
- reconcile: checks uncommitted changes -> WARN, branch divergence, checkpoint age, never blindly resume
- recover: restore checkpoint if safe, else escalate
- resume: alias for recover

## Known Limitations (Honest)

2. [LOW] Adapters only example mappings, not full SDK integration - intentional for provider independence
3. [LOW] Cost telemetry fields exist but actual token counting per provider not implemented - optional per spec
4. [MED] CI workflow only runs gate tests, not new tests (state_machine, permissions, recovery, playbook) - should be updated in next iteration
5. [LOW] Knowledge promotion not fully automated - requires manual review, intentional for safety
6. [LOW] Worktree fallback to directory isolation if git worktree fails - intentional for envs without git
7. [INFO] .eng/runs/.seq file for run ID generation uses simple file counter, not atomic - may race in parallel, acceptable for single-agent use
